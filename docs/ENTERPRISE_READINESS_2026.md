# Enterprise readiness review — 31 August 2026

## Executive verdict

Ask Your Data is a strong, unusually inspectable analytics prototype. It is
appropriate for a portfolio, a controlled internal pilot over non-sensitive
data, or as the query-engine core inside a larger product. It is **not yet a
world-class enterprise AI service** and should not be represented as one.

The central strengths are real: all answer values originate in DuckDB, SQL is
shown, model output is treated as untrusted, filesystem/network table readers
are denied, execution is bounded, a deterministic keyless compiler exists, and
the repository carries broad offline contracts. The remaining blockers are not
UI polish. They are identity, tenant/data policy enforcement, semantic
correctness coverage, durable service architecture, supply-chain controls, and
production operations.

## Review evidence

This review inspected the application, engine, tests, CI, container,
configuration, and browser-rendered UI. It also ran the complete offline suite,
Ruff, planner and retrieval evaluations, the UI audit, focused adversarial
reproductions, and dependency consistency checks. The only intentionally
unexercised contract is the live Anthropic model evaluation because no valid
Anthropic key was available.

Measured before this remediation:

- 790 tests passed and one live-model test skipped.
- The ordinary planner contract answered 46 correctly, refused 12 required
  cases, and produced no wrong result among answered cases.
- On the model-oriented golden contract it answered five of six attempted cases
  correctly and conservatively refused the rest; this is not a production
  accuracy claim.
- Hybrid schema retrieval reached 100% table and question recall at k=10 in the
  committed evaluation, using roughly 2,253 schema tokens. Vector-only recall
  was 94.9%.
- The automated UI contrast audit passed its tested panels; the lowest measured
  text contrast was 4.94:1.

The current post-remediation test count belongs in the release evidence, not in
this point-in-time section, and must be regenerated by CI rather than edited by
hand.

## Confirmed defects corrected in this pass

| Area | Confirmed defect | Remediation |
|---|---|---|
| Local model provider | Answer summarization posted to `/chat/completions` while SQL generation used `/v1/chat/completions` | Both now use the versioned OpenAI-compatible route, with an offline route contract test |
| Model tool contract | `answer_with_sql` with missing `sql` crashed with `KeyError` | Invalid payloads enter the bounded correction loop and end in an honest refusal |
| Provider tool parsing | A non-object Anthropic tool payload crashed during `dict(...)` conversion | Provider normalizes malformed input to an empty payload for safe validation |
| Retrieval reliability | A deleted/dead Chroma collection forced full-catalog prompts until process restart | Dead handles are cleared, the failing turn falls back safely, and the next turn rebuilds under a lock |
| Concurrent retrieval | Process-global Chroma construction was not serialized | Index lifecycle is protected by a re-entrant process lock |
| Exemplar reliability | A stale/deleted Chroma exemplar handle intermittently returned no neighbor | Exemplar index lifecycle is serialized and query failure rebuilds once before degrading |
| SQL denial of service | Validation/parser work accepted arbitrarily large pasted SQL before the execution watchdog | SQL is bounded at 20,000 characters at the guard boundary and in the editor |
| Question bounds | Typed questions had no server-side length boundary | Both UI and assistant enforce a 400-character maximum |
| Audit latency | Model turns recorded zero latency because only absent stage timings were summed | Audit uses the measured model round-trip when present |
| Audit grounding | Model audit records had no actual prompt-table list | `AskResult` now carries prompt tables, retrieval context, and schema token estimate |
| UI grounding | Follow-up panels re-retrieved the standalone question and could disagree with the prompt | Model readouts use the actual retrieval context and exact prompt-table membership |
| Session operations | “This session” aggregated the process-global ring across all browsers | Operations summaries filter by the current actor/session |
| Audit sink health | File-sink write errors were swallowed with no operational signal | Sink error state is visible in the operations summary while answers remain available |
| Failed provider calls | `st.stop()` discarded provider failures before transcript, count, and audit | Failures now produce a safe transcript entry and an `error` audit record |
| Credential reset | Switching back to the compiler cleared `byok` but the keyed widget immediately restored it | Both authoritative and widget state are cleared |
| Verifier | A non-unique self-join could multiply an aggregate while all checks passed | Alias-aware self-join fan-out is now a blocking `join_fanout` finding |
| Container | Build context could contain ignored secrets and the service ran as root with no health check | `.dockerignore`, non-root user, ownership, and Streamlit health check added |
| Dev container | Python 3.11 disagreed with the 3.12 project and disabled CORS/XSRF | Aligned to Python 3.12 and restored Streamlit protections |
| Voice privacy/cost | Voice required a paid key and the disclosure contradicted the network behavior | Free local faster-whisper/Kokoro path added; cloud fallback disclosure now names what is sent |
| Voice memory | Generated answer audio accumulated for the session | Cache is bounded to the three most recent generated clips |

## New optional capabilities

### Free, self-hosted speech

`compose.local.yml` runs Speaches on CPU and configures the existing OpenAI SDK
seam to use it. The default local models are:

- STT: `Systran/faster-whisper-small`
- TTS: `speaches-ai/Kokoro-82M-v1.0-ONNX`
- Voice: `af_heart`

No paid API key is required. A transcript is still editable and must be
confirmed before it becomes a question. TTS remains on demand. OpenAI voice is
retained only as an explicit cloud fallback.

### n8n operations workflow

The application can enqueue a signed, non-blocking event after an audit record
is written. The allow-list contains operational metadata only. It excludes the
question, SQL, data values, refusal reason, guard explanation, and correction
feedback. The importable n8n workflow verifies the HMAC and classifies errors,
timeouts, guard failures, and ten-second latency breaches for downstream alert
routing.

n8n does not execute or approve SQL and is not a dependency of the answer path.
Its self-hosted license is fair-code/source-available rather than OSI open
source; legal review is required before embedding it in a commercial offering.

## Remaining release blockers

### P0 — required before sensitive or multi-tenant production use

1. **No authenticated identity or authorization boundary.** The `actor` is a
   random browser-session label. There is no SSO/OIDC, RBAC/ABAC, service
   account, tenant identifier, policy decision point, or administrator role.

2. **No data-plane enforcement.** Every accepted SELECT can read every loaded
   table and column. A real deployment needs tenant-scoped database principals,
   row-level security or policy views, column masking, purpose-based access, and
   denial tests executed against the same credentials as the query.

3. **Known semantic wrong-answer space remains.** Deterministic checks now catch
   structural fan-out, including self joins, but cannot generally infer a
   missing business filter, a wrong metric denominator, or reversed business
   intent from valid SQL. Reproductions remain committed for denial-rate
   denominator, dropped `is_active`, and reversed top/bottom sort. Enterprise
   release needs governed metric contracts and question-to-plan conformance for
   every decision-critical KPI, not a promise that arbitrary SQL can be proven
   semantically correct.

4. **No production data governance.** The current warehouse is synthetic.
   There is no sensitivity catalog, owner/steward workflow across all columns,
   lineage to production sources, consent/purpose metadata, retention/deletion
   policy, legal hold, data residency control, or subject-access workflow.

5. **No durable, tamper-evident audit architecture.** JSONL plus an in-memory
   ring is useful evidence for a prototype, not a regulated system of record.
   Production requires authenticated identities, centralized append-only/WORM
   storage, encryption, retention, access review, integrity protection, and
   reconciliation for requests lost during process failure.

### P1 — required for a reliable enterprise service

1. **Single-process, in-memory service.** DuckDB state, audit ring, session
   state, and retrieval handles are local to one process. There is no shared
   durable state, horizontal-scaling contract, leader/worker separation,
   failover, backup/restore test, or disaster-recovery objective.

2. **No service-level objectives or end-to-end telemetry.** Per-turn timings are
   strong, but there is no OpenTelemetry trace, central metric backend,
   availability/latency SLO, error-budget policy, synthetic probe, pager route,
   or tested incident runbook. n8n provides a safe extension point, not the
   missing operations program.

3. **No enforceable cost/rate boundary.** The 60-question session limit is
   bypassed with a new session. Public model deployments need gateway identity,
   per-principal quotas, concurrency limits, provider spend caps, token budgets,
   admission control, and abuse monitoring.

4. **Incomplete model operations.** The live model evaluation is not a required
   CI/release gate, model aliases are mutable, and there is no champion/challenger
   process, signed prompt/model release, drift monitoring, hallucination review
   queue, or rollback decision policy.

5. **Residual prompt/data injection.** Raw query rows are sent to the answer
   summarizer and that summary can be replayed as conversation context. Host
   file/network reads are closed and error text is clipped, but production still
   needs explicit trust-zone tagging, content isolation, output policy checks,
   and adversarial tests using realistic untrusted warehouse values.

6. **Query planning outside the execution watchdog.** SQL length is now bounded,
   but verifier parsing, uniqueness probes, `EXPLAIN`, and `DESCRIBE` are not all
   governed by the same request deadline. One deadline/cancellation context
   should cover retrieval through rendering.

7. **Supply-chain assurance is incomplete.** Runtime requirements use broad
   ranges and there is no committed lock, hash verification, SBOM, provenance
   attestation, dependency vulnerability gate, secret scan, SAST, container
   scan, or license inventory. The project environment was internally
   consistent during review; reproducibility is the gap.

8. **n8n/Speaches production hardening is not supplied.** The Compose file is a
   local profile. Default placeholder secrets must be replaced; n8n needs real
   authentication, TLS ingress, backup, database, least-privilege credentials,
   egress policy, upgrade testing, and a reviewed Sustainable Use License use
   case. Speech model artifacts need version/digest pinning and model-license
   review.

### P2 — quality and accessibility debt

- Automated contrast passed and primary inputs/buttons now carry 44-pixel touch
  targets, but framework data-grid/icon controls still need device validation;
  the sidebar heading can precede the page H1 in reading order, and icon glyph
  names/unnamed canvas elements can leak into the accessibility tree.
- Main/navigation/aside landmarks are incomplete.
- Manual NVDA/VoiceOver, keyboard-only, 200%/400% zoom, speech-input, and mobile
  touch certification has not been performed.
- Load, soak, concurrency, cold-start, audio-size, and recovery testing is absent.
- Public API/versioning, client compatibility, deprecation, and data-contract
  processes do not exist because the current product is a Streamlit UI.

## Enterprise completion gate

Do not label the product enterprise-ready until all of the following have
release evidence:

- OIDC/SSO identity and role/tenant claims enforced at the data plane.
- RLS/masking negative tests proving cross-tenant and restricted-column denial.
- Governed definitions and expected-value contracts for every critical KPI.
- Live model and adversarial evaluations required for the exact released model.
- Durable encrypted audit export with tamper evidence and retention policy.
- SLOs, alerts, on-call runbooks, load/soak results, backup restore, and DR drill.
- Locked dependencies, SBOM, signed image, vulnerability/license/secret gates.
- Threat model and independent penetration test covering model and ordinary web paths.
- WCAG 2.2 AA audit with assistive-technology evidence and remediated touch targets.
- Legal/privacy review for models, data, voice processing, and n8n licensing.

Until then, the accurate label is: **governed, test-heavy analytics AI
prototype with an enterprise migration path**.
